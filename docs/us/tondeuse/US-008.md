## User story

En tant qu'opérateur, je veux décrire plusieurs tondeuses dans un même fichier, afin d'obtenir la position finale de chacune, dans l'ordre du fichier.

## Incrément de valeur

L'exemple de référence de l'énoncé passe en entier : la CLI pilote une flotte de tondeuses en un seul appel.

## Critères d'acceptance

- [x] CA-1 : étant donné le fichier de l'exemple de référence (`5 5` / `1 2 N` / `LFLFLFLFF` / `3 3 E` / `FFRFFRFRRF`), quand je lance la CLI, alors stdout contient exactement `1 3 N\n5 1 E\n` et le code de sortie est `0`. *(réf. spec : RM-12, O-1)*
- [x] CA-2 : après la ligne de la pelouse, chaque tondeuse est lue comme un couple de lignes consécutives (position, puis instructions), quel que soit le nombre de tondeuses. *(réf. spec : RM-04)*
- [x] CA-3 : les tondeuses s'exécutent l'une après l'autre : la tondeuse n+1 ne bouge qu'une fois que la tondeuse n a exécuté toute sa séquence. *(réf. spec : RM-10)*
- [x] CA-4 : la sortie contient une ligne par tondeuse, dans l'ordre du fichier, chaque ligne terminée par `\n`, y compris la dernière. *(réf. spec : RM-11)*

## Contraintes techniques (héritées du .tech.md)

- Le modèle validé contient la liste ordonnée de toutes les tondeuses. Il est construit en entier avant le premier déplacement (deux phases strictes).
- `MowLawnUseCase` fait écrire les positions finales dans l'ordre du fichier.

## Hors scope

- Interactions entre tondeuses : blocage par une case occupée (US-tondeuse-002) et départs en doublon (US-tondeuse-005).
- Exécution simultanée : hors scope de la spec (RM-10).
